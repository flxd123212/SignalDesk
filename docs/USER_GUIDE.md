# SignalDesk 使用手册

[返回项目首页](../README.md)

本手册保留设备、协议、工具链、Agent 与数据存储的详细配置说明。

Windows 本地嵌入式开发与调试工作台，整合工程、源码浏览、编译测试、Agent、串口和仪器数据。React / Electron / Node.js，实际串口使用 serialport，波形使用 uPlot，FFT 使用 fft.js，节点使用 React Flow，编辑器使用 CodeMirror。默认保持离线、等待真实设备，不会自动启动模拟采集。模拟信号仍可在串口列表中手动选择。

## 从一个任务开始

- 首次打开主窗口显示一条可关闭的入门提示，不自动弹出强制向导；关闭后不再反复提示。独立仪器窗口不显示这条提示。
- “帮助 > 使用教程”、左下角书本图标或功能搜索中的“使用教程”打开内置教程；`F1` 定位到当前页面对应的课程。教程随软件打包，阅读不需要联网或 AI Key。
- 基础课程包括第一台设备、导入与编译、波形频谱与节点、硬件引脚、自动测试报警、Agent 和常见问题；指令协议、仪器/CAN、脚本控件和模型姿态等进阶课程默认收起，搜索时仍能找到。
- 每一步都有操作、预期结果和必要的风险提示。“打开设置”等按钮只定位对应面板，不自动发送命令、编译、烧录或调用模型；离开教程后通过顶部“继续教程”返回。
- 步骤位置和完成记录随偏好保存，可在教程中重学；恢复默认布局不会清除学习进度。“设置 > 学习与帮助”可重新启用入门提示。
- 功能搜索也提供添加项目、连接设置、设置和精简/完整模式等快捷操作，不必记住每个功能在哪个工作区。

## 启动

- Windows x64 安装版：运行对应版本的 `SignalDesk-Setup-<版本>-x64.exe`，可选择目录并创建桌面、开始菜单快捷方式。
- 单文件免安装版：运行对应版本的 `SignalDesk-Portable-<版本>-x64.exe`。首次启动会解压运行环境；配置保存在当前用户目录，不随 EXE 放入 U 盘。
- 两种发行版都包含 Electron/Node.js，无需额外安装 Node.js。GCC、Keil、IAR、驱动和器件包仍使用本机安装。
- 双击 `launch.cmd`，或者运行 `npm start`。
- 浏览器版：`npm run serve`，默认 `http://127.0.0.1:4780`；端口被占用时使用后续空闲端口。
- 开发模式：`npm run dev`。构建：`npm run build`。
- 新环境需要 Node.js 22.12+，执行 `npm install`、`node node_modules/electron/install.js`、`npm run build`。Electron 45 的二进制使用单独的安装命令。
- 桌面菜单“文件 > 新建独立工作区窗口”打开另一套独立本地服务。一个窗口内最多 8 个并行设备，多个窗口不能重复占用同一实际串口。

## 设置与独立窗口

- Windows 桌面版将窗口标题栏与软件菜单合并，保留原生最小化、最大化、关闭和拖动缩放。文件菜单仍可创建独立工作区，编辑菜单保留复制、粘贴等操作。
- 后台每秒扫描系统串口，通过实时连接同步所有页面。插入新 COM 口时弹出“发现新设备”，可选择已有工程或新设备、波特率与数据格式，再仅绑定或连接。已连接设备不会被自动替换。
- 右上角插头、“工具 > 发现设备”或“设置 > 设备与连接”可手动打开设备弹窗；自动弹窗可关闭。启动时已有端口会列出，不主动抢占；独立工具页不重复弹窗。
- 通用 CH340、CP210x 等接口不能单凭 USB 信息判定下游 MCU 型号。系统未枚举 COM 时显示检查提示，扫描失败保留上次列表并禁用连接，避免误报设备拔出。
- 左上角“设置”、右上角齿轮或 `Ctrl+,` 打开统一设置，包括外观、编辑器、设备连接、AI 接口、编译工具链和 Agent 权限入口。
- 可选择常用功能、强调色、启动页、代码字号与换行，显示/隐藏顶部布局按钮和工作页标签，设置串口发送栏的自动/始终/收起模式；其余功能从“工具”菜单打开。
- 偏好可导入、导出 JSON；导出不包含模型密钥、外部 Agent 令牌或设备操作权限。桌面端保存在用户数据目录的 `preferences.json`，重启后恢复。
- Agent 的会话与持续分析选项从标题栏下拉按钮展开；“项目与执行”显示源码、修改记录、提案和工具链。源码/Agent 等页面默认收起串口发送栏，可在底部展开。
- 右上角“在独立窗口打开当前页”或“视图”中的同名命令打开工具窗口，适用于第二屏。它共享原工作区的采集、活动设备和 Agent；关闭单个工具窗口不会停止仍在使用的工作区。需要隔离设备与会话时使用桌面“文件 > 新建独立工作区窗口”。
- 浏览器版通过浏览器弹窗实现同一功能，需允许本站弹窗。

## 动画、主题与背景

- “设置 → 外观与布局”可关闭全部界面动画、单独关闭启动动画，选择“柔和”或“灵动”，也可预览启动画面。系统减少动态效果设置优先，独立工具窗口直接进入工作区。
- 启动动画包含电路走线和信号轨迹，阶段依据前端加载、WebSocket 连接与首个工作区快照更新。工作区就绪后自动结束，默认展示约 1.1 秒，可立即跳过或按 Esc。超过 12 秒仍未就绪显示重新加载/进入工作区，不显示虚构百分比。
- “设置 → 主题与背景”支持取色器及 `#RRGGBB` / `#RGB` 颜色输入。主按钮前景色根据主题色亮度选择。提供实时预览与恢复默认主题。
- 背景可选默认、纯色或本地图片；支持 PNG、JPG、WebP，源文件上限 8 MiB、4000 万像素，保存前缩放至最长边 2048px 并转换为不超过 2 MiB 的 WebP。
- 图片可填充或完整显示，模糊为 0–12px，背景遮罩为 20–90%。模糊只作用于背景层，不模糊文字、源码或波形。
- 桌面背景保存在用户数据目录 `appearance/background.webp`；浏览器版使用当前站点 IndexedDB。偏好 JSON 仅保存图片标识和显示设置，不包含图片内容。跨机器导入偏好后需重新选择图片；同一机器重启无需重选。
- “移除图片”删除当前背景副本；“恢复默认主题”隐藏图片并恢复默认颜色，保留图片以便切回。背景不会发送给 AI 或其他网络服务。

## 构建 Windows 发行版

```text
npm install
npm run package:win
npm run test:package
```

`electron-builder.yml` 生成 NSIS 安装包和 Portable EXE。`release/win-unpacked/SignalDesk.exe` 可用于调试，但分发时必须保留旁边的资源文件，不能只复制该 EXE。免安装分发使用 `SignalDesk-Portable-*.exe`。

程序包只包含运行代码、静态资源及示例模板，不包含 `.data`、日志、测试产物、用户工程或第三方编译器。首次启动将模板复制到用户数据目录 `examples/`，之后不会覆盖用户编辑。卸载默认保留配置、录制和示例工程。

当前发行版未做代码签名。首次打包需要下载 NSIS/7zip；网络无法连接官方分发时可按本机网络情况设置 `ELECTRON_BUILDER_BINARIES_MIRROR`，构建工具仍会校验组件哈希。

## 连接设备与工程

顶部“添加项目”是统一入口。桌面版选择目录后自动扫描；浏览器版输入本机工程绝对路径后识别。核对构建目标与串口，再点“添加并连接”；未接开发板时可直接添加离线项目。它同时配置设备名称、芯片/板卡线索、USB 身份绑定、串口参数、协议线索、源码入口、构建目标和 Agent 工程上下文。已导入的同一工程目标默认切换到现有设备；勾选“为另一块板新建设备”可另建绑定。最多 8 个设备。

识别读取工程配置与有限源码，不执行工程脚本，也不主动发送芯片探测指令。多个构建目标或多个等价串口候选需要选择；CP210x、CH340 等通用桥接器不能单独证明 MCU 型号。未知数据格式使用 Raw；源码推断的波特率、协议和采样率可在导入详情中更正。自动跟踪 COM 号要求唯一 USB 身份，连接仍由用户触发。未匹配串口的工程保持离线，不会自动改成模拟设备。

可选复用当前设备已配置的 AI 接口，但新建独立会话；桌面版在用户目录加密保存密钥。导入不授予外部 Agent 写入、发送或工具链执行权限。项目体检完全本地运行，检查绑定、主文件、工具位置、采集状态与解析计数；检测到可执行文件不代表许可证、依赖、SDK 或真实编译已经验证。ESP-IDF 需要从已激活的 ESP-IDF Python 环境启动应用；纯 Arduino `.ino` 项目缺少 FQBN 时可先监测，编译前补充开发板。

## IDE 布局与精简模式

“文件 / 视图 / 工具”菜单集中项目与布局操作。左侧默认使用窄图标栏，项目文件树和连接设置共用一个可收起侧栏；中间工作页与源码文件分别使用标签；右侧 Agent、底部日志/工具链按需展开。拖动分隔线可调整尺寸，分隔线也支持方向键和双击复位，“视图 > 重置界面布局”可统一复位。

源码视图默认收起重复连接信息、搜索/行号跳转和串口发送栏。文件树打开的源码为只读，支持搜索与定位，并可交给旁边的 Agent 生成审查或修改提案；原有修改前后对照、备份和确认执行保持有效。Agent 分栏默认折叠会话与持续分析设置，主 Agent 页面仍提供完整控制。底部工具链命令绑定发起设备和工程，切换后到达的旧请求会被拒绝。

C/C++/Arduino 源码按语法着色，区分关键字、函数、类型、字符串、数字和注释，支持代码折叠与函数/类型大纲跳转。左侧显示打开的编辑器，底部显示光标行列。`Ctrl+P` 快速打开文件，支持 `文件名:行号`；`Ctrl+B` 切换侧栏，`Ctrl+J` 切换底部面板，`Ctrl+Shift+B` 编译当前工程。源码大纲是语法分析结果，不是完整 C/C++ 语言服务器；宏展开、跨文件符号和语义诊断仍依赖编译器。

精简模式保留常用入口，默认收起侧栏、Agent 分栏、底部输出和示波器高级参数。完整模式的布局偏好单独保留；其余功能仍可从搜索或菜单打开。工作页切换保留已打开示波器的暂停、触发和量程状态，关闭该工作页或切换设备会重新建立视图。文件标签按设备/工程区分，发送草稿也按设备隔离。

工程根目录可放置可选的 `signaldesk.json`，覆盖静态推断。只使用明确的配置字段，不执行文件内容：

```json
{
  "version": 1,
  "name": "S3 Telemetry",
  "chip": "ESP32-S3",
  "board": "ESP32-S3-DevKitC-1",
  "serial": { "baudRate": 230400, "protocol": "firewater", "sampleRate": 200 }
}
```

本地接口：`POST /api/projects/prepare` 接收 `{ "root": "工程绝对路径" }`，返回短期扫描计划及候选；`POST /api/projects/apply` 使用计划 `id`、`targetId`、可选 `port`/`connect`/`reuseAI`/`newDevice` 应用；`POST /api/ai/project-health` 接收 `deviceId`，将本地体检记录进当前 Agent 会话。应用前重新校验工程指纹与串口身份，不接受被替换的旧扫描结果。

顶部搜索或 `Ctrl+K` 可以按功能名、关键词、设备名或芯片型号跳转，方向键选择、Enter 打开、Esc 关闭。连接栏、导航文字和实时监测中的终端可以独立收起；浏览器持久保存布局开关和面板尺寸。

每个设备的发送内容、格式、编码、结束符、校验与间隔分别保留。最近记录最多 30 条，仅记录成功的手动发送；选中记录只填回输入框。草稿和历史只保留在当前页面内存，刷新或关闭窗口即清空。文件发送和定时发送请求绑定发起时的设备，服务端发现设备已切换会拒绝该请求。

暂停波形时，通道读数和 CSV 使用同一份冻结缓存；单次触发导出捕获数据。CSV 导出的是这份数据缓存，不受屏幕缩放范围裁剪，后台采集仍可继续。

设备标签中的 `+` 添加设备。左侧选择串口与线路参数；网络仪器使用 `tcp://主机:端口`，常见 SCPI 原始 TCP 端口为 5025，具体以仪器手册为准。

左侧“设置”打开设备与工程弹窗，可浏览目录、扫描 Keil/IAR 工程芯片、查看 USB 描述符与启动日志提示。CH340/CP210x 等桥接芯片不能证明目标 MCU 型号；每条提示保留证据与确认边界，不会覆盖用户标记。唯一 VID/PID/序列号可绑定工程并匹配变化后的 COM；没有序列号的接口仅固定端口绑定。匹配不会自动打开串口。切换设备时，采集、计数、处理链和 Agent 会话独立；重启不自动连接真实设备。

串口页支持系统配对后的 SPP 虚拟 COM。低功耗设备请在工程实验工具中打开蓝牙 GATT。串口接受 50..12000000 的整数波特率请求，实际范围取决于硬件和驱动。

自定义帧先在“自定义帧”保存 JSON 配置，断开设备后在“数据协议”选择自定义二进制帧并连接。帧头 1..16 字节，帧长 2..4096 字节，最多 16 个数值字段；支持 u8/i8/u16/i16/u32/i32/f32/f64、LE/BE、CRC16 Modbus/SUM8。修改配置后需要重新连接。

采样率必须与固件实际发送速率相符。软件时基取自配置采样率，不是硬件时间戳；丢帧、非均匀采样和混合日志会影响频率与 FFT。它不能直接测量未接入 ADC 的物理信号，也不替代真实示波器。

## 编译、测试与 GCC

源码工具栏的锤子按钮编译当前绑定工程，试管按钮打开测试面板。底部“构建与测试”提供构建设置、配置、编译、测试目标、停止，以及输出/问题/记录/产物视图；错误或警告可跳转到工程内的文件行。验证报告可导出 JSON，也可将失败上下文填入 Agent 请求供审查，不自动调用模型。

- 本机 CMake：先配置 `build`，再编译和运行 CTest，支持 Debug/Release 等配置。CTest 之前要求当前本地源码与配置存在成功构建记录，避免测试旧程序。无用例不会显示通过。
- PlatformIO：`native` 环境执行测试；板端环境只编译测试固件，不默认上传或运行板端测试。未识别用例计数时会明确显示数量未知。
- GCC：在工程构建设置中选择“GCC 交叉编译”，选择交叉编译器绝对路径与工程内 `.cmake` 工具链文件，再“配置 GCC 工程”和“编译工程”。使用 CMake/Ninja，不是直接对单个 C 文件随意拼接参数，也不是自动转换 Keil 工程。CPU、浮点 ABI、RISC-V ISA、链接脚本、SDK 和启动文件由工具链文件及工程定义。
- 已接入 `arm-none-eabi-gcc` 与常见 `riscv32/riscv64/riscv-none-elf-gcc` 命名；扫描 PATH、常见 Arm 安装目录、PlatformIO 位置与本机海思工具包。可手动指定未扫描到的位置。当前真实交叉编译验证使用本机 `riscv32-unknown-elf-gcc 7.3.0`，ARM 未在本机实编译。
- GCC 配置使用独立的 `build/gcc-<配置标识>` 目录，成功时列出实际 ELF/BIN/HEX/MAP/静态库文件，读取 ELF 头显示架构。交叉 ELF 不能直接当作 Windows 本机程序运行；板端测试需要对应设备或仿真器。ESP32 的 SDK 工程继续使用 ESP-IDF / PlatformIO。

`firmware-examples/CrossCompileCheck` 提供可导入的 ARM/RISC-V 编译链路示例，生成 ELF/MAP；没有复位向量和板级初始化，不可直接烧录。编译通过仅说明工具链接受了代码，测试通过只覆盖执行的用例，设备时序与硬件行为仍需实测。

验证面板每设备/工程保留本次服务运行的最近 10 条结果，完成记录另写入审计日志。任务最长 10 分钟，CTest 单用例默认 30 秒，输出保留末尾 64,000 字符。源码指纹包含工程内常见源文件、头文件、Drivers、链接文件和测试脚本，排除构建目录与外部依赖缓存；上限 10,000 文件 / 64 MiB / 单文件 8 MiB，暂不跟踪符号链接源码。编译期间本地源码改变会标记需要重新验证；指纹不能覆盖系统 SDK、编译器和工程外部依赖的变化。

## Keil 与 IAR

已加入本机路径自动查找：

- Keil：`D:\Keil5 C51\UV4\UV4.exe`。本机检查版本为 5.14，另有 ARMCC 5.05 与 C51 9.54。
- IAR：`D:\IAR\common\bin\IarBuild.exe`。本机 IarBuild 6.1.7，已检测到的编译器为 8051 8.10.3。
- `D:\IAR\common\bin\CSpyBat.exe` 已检测到，但未提供任意芯片的通用下载配置。

“芯片与固件”会列出绑定目录内的 `.uvproj/.uvprojx` 和 `.ewp`，显示 Target/Configuration、芯片或工具链、工程文件。也可在 AI 设置中选择构建工具并设置路径。

Keil 编译使用 `UV4 -b <project> -t <target> -o <log> -j0`，下载使用 `-f`。下载前必须已有构建输出，软件记录工程、下载器选项和输出文件的哈希；确认前发生变化会拒绝执行。必须配置匹配的器件包、Flash Algorithm、下载器及驱动。它不是通过任意串口下载所有芯片。

IAR 编译使用本机帮助验证过的 `IarBuild <project.ewp> -build <configuration> -log all`。当前 IAR 安装为 8051，不能据此认定可编译 STM32 或 ESP32。C-SPY 下载涉及处理器 DLL、驱动 DLL、调试输出和具体探针配置，目前没有自动生成或执行这些参数。

ESP32 使用官方 esptool；STM32 使用 STM32CubeProgrammer CLI。这些软件需单独安装。下载需要显式选择文件、芯片、地址和端口，预览任务后输入目标确认；不会自动擦除全片、绕过保护或自动烧录。

## Agent 与权限

内置本地分析不访问模型。AI 模式需要配置 Base URL、模型 ID 和 API Key。桌面版将密钥、配置与会话加密保存在本机，重启自动恢复；密钥不写入浏览器偏好、工程或日志。独立 Node 服务不提供系统加密时，密钥仅保留在内存，其他设置与文本会话仍可保存。

Agent 工具箱可查看 18 个工具及当前权限状态。工具调用可以展开查看参数、结果和耗时，并打开相关源码行。展开会话设置可搜索历史，`/continue` 可填入继续任务的请求。任务计划、会话记录和模型续接会在桌面重启后恢复，但不会自动执行上次未完成的操作。单会话保留最近 300 条、512 KiB 记录，长期归档可使用 Markdown 导出。

“设置 → 外观与布局 → 界面动画”控制消息、弹窗、菜单及运行状态的动画，系统减少动态效果设置同样生效。

DeepSeek 官方地址选择 Chat Completions，不能与 Responses 格式混用。支持模型列表、超时/输出上限和连接诊断，见 [AI 接口](AI_PROVIDERS.md)。真实 PCB 导出样例及限制见 [PCB 实测](PCB_EXPORT_SAMPLE.md)。

每个设备最多 12 个会话。子代理分为数据诊断、固件审查、验证方案，只有读取权限；结果汇总回父会话。修改、串口指令、构建默认生成提案，用户审查后应用。固件文件须为 UTF-8，源码浏览与局部补丁支持单文件 8 MiB。模型整文件读取上限 32000 字符；附带较大文件时自动提供标明范围的摘要片段和完整 SHA256，再按需使用 `read_firmware_lines` 读取。整文件替换仍限 96 KiB，大文件使用 `propose_source_patch`，防止片段覆盖原文件。模型只读子代理并不等于后台无限任务。

“外部 Agent”生成 Codex TOML、通用 MCP JSON、HTTP 或 PowerShell CLI 配置。不同客户端可调用同一接口，不依赖内置模型。无需修改用户全局配置。没有令牌时间有效期，通过连接/断开和权限切换控制；服务重启仍使令牌失效。详细工具与权限见 [外部接口](EXTERNAL_AGENTS.md)。

权限独立可选：读取、提交建议/提案、直接写文件、直接发设备指令、直接执行工具链。后三项默认关闭；启用后这些动作不再逐次询问。撤销权限阻止后续调用，正在进行的构建会尝试停止；已经发出的字节或已应用的改动不会被自动撤回。烧录不包含在外部授权中。

直接写入同样先验证 SHA256、保存原文件并记录差异。读写仅限绑定工程的已有受支持源码文件，不能借路径穿越访问外部文件。改绑工程后旧连接失效；重连设备后旧串口发送授权失效。外部连接令牌在服务重启后失效。

这些权限控制的是 SignalDesk 接口，不是操作系统沙箱，不能限制第三方 Agent 自带的终端或文件工具。构建可能运行工程自带脚本，只对可信工程开放工具链执行。向模型或外部 Agent 提供源码意味着相应服务可读取所授权内容。

## 自动测试

测试脚本是 JSON，不执行任意 JavaScript/Python。支持 `send`、`wait`、`expect`、`assert`，例如：

```json
{"name":"identity","steps":[
  {"type":"send","text":"*IDN?","format":"text","ending":"lf"},
  {"type":"expect","contains":"SIMULATOR","timeout":2000},
  {"type":"wait","ms":200},
  {"type":"assert","channel":0,"min":0,"max":3.3}
]}
```

脚本运行期间锁定该设备的人工/Agent 发送；断开设备会取消测试。最多 100 步，累计等待不超过 5 分钟。

## Agent 停止后怎么继续

计划的 `0/3` 表示三个事项尚未完成，不是模型轮数。任务没有固定轮数，刷新工作区不会中止服务中的任务；停止按钮仍可随时使用。持续监测的“20 个窗口”是另一项设置。长任务可能产生多次模型调用和费用。

**从口语需求到项目交付**

1. 打开目标工程，选择芯片和串口。在 Agent 输入原话，例如“按键切换 OLED 上的温度和湿度，不要改现有串口协议”。点击“整理提示词”生成可编辑草稿，也可以还原原话。整理不会执行操作，也不会把猜测的阈值变成需求。
2. 选择“项目交付”并发送。Agent 可核对工程文件、导入的网表、引脚映射和部分开发板的官方参考；缺少板号或实际接线时，在“补充需求”处回答。原理图文件名本身不证明线路正确。
3. 核对工程提示词和验收条件，选择逐项询问或仅对本次任务直接授权。直接授权涉及写文件、执行本机工程构建脚本及发送已知串口命令，仅用于可信工程。拒绝会作为工具结果返回，不是执行成功。
4. 在 Agent 查看新增/删除行，打开修改位置；生成的 `.screen.json` 界面支持页面预览。构建退出码、设备发送和实测是不同证据。测量窗口只统计新收到的设备通道值，无数据会明确标记。不能自动证明已烧录或实物接线正确。
5. 收到交付结果后点击“验收完成”，或输入反馈点“继续改进”。服务退出不会自动恢复直接执行授权。

继续会保留原任务与已完成的工具证据，重新读取当前工程/设备数据。原只读任务不会升级权限，修改、串口和工具链仍需原来的确认流程。恢复旧版本存档时没有完整参数的任务默认只读。等待模型时会显示已等待秒数。

如果正文出现 DSML 工具标记，新版会明确报告格式异常而不是显示成功。可以手动继续；若反复出现，需要检查服务商或转发接口是否正确支持标准工具调用，不要将这些标记当作已经执行的操作。

展开 Agent 会话设置可查看有界历史摘录；摘录中的旧建议未经重新验证，不能替代当前源码、SHA256、构建和设备结果。详见 [Agent 运行说明](AGENT_RUNTIME.md)。

## 数据与日志

浏览器服务数据在 `.data/`。桌面主窗口数据在 Electron 的 `userData` 下，额外窗口使用各自的 `windows/<编号>/`。

- `devices.json`：设备与工程、工具链绑定，不含密钥。
- `sessions/`：原始串口录制；单次导入/回放不超过 32 MiB。
- `firmware/`：导入的固件和版本/SHA256 元数据。
- `changes/`：修改前后源码、差异、状态、备份位置，可能包含敏感工程内容。
- `logs/`：审计日志，每卷 8 MiB，最多当前卷加 4 个历史卷；界面显示最近 500 条匹配记录，导出读取保留卷。
- 工程下 `.signaldesk-backups/<修改ID>/` 保存修改前文件，`.signaldesk-build/` 保存工具链输出。

波形界面保留 12000 点，后端每设备统计保留 2048 点；终端保留 1000 个包，长时间完整记录需开启录制。单次发送/文件发送上限 64 KiB。

## 验证与边界

按 `Shift+F1` 打开快捷键清单，可以按功能名或按键筛选。`F6` 发现设备，`F7` 编译当前工程，`Shift+F7` 打开测试目标选择，`F8` 查看编译问题，`Shift+F8` 查看固件容量。按 Control 加反引号可打开串口终端。

容量页读取本次构建输出中的 GNU ld 分区表、PlatformIO 容量摘要或 Arduino 英文容量摘要，显示已用字节、容量和余量。该数据反映构建时的静态占用。选择历史记录后可以查看对应构建的容量，导出验证报告时会一并保存。`CrossCompileCheck` 示例自带链接器分区表。

### 从异常日志定位源码

按 `F9`，或从「工具 → 崩溃回溯」打开。选择本次烧录对应的工程内 `.elf`、`.axf` 或 ELF 格式的 `.out`。窗口会读取最近的串口接收缓存，也可以粘贴历史日志、GDB 帧或十六进制指令地址。点击「解析地址」，再点击帧中的文件名即可跳到源码行。下载按钮可保存含原始地址、查找地址、工具名和 ELF 指纹的报告。

| 固件架构 | 常见目标或输入 |
| --- | --- |
| Arm | STM32、GD32 的 Arm 型号、RP2040、nRF52、NXP i.MX RT 等 Cortex-M 工程。支持 HardFault 的 PC / LR、Zephyr 异常地址和 Thumb 地址。 |
| RISC-V | GD32VF、CH32V、Hi3861 和 ESP 的 RISC-V 型号等。支持 MEPC、SEPC 和 RA。 |
| AVR | ATmega、ATtiny。根据日志产生方式选择字节地址或 AVR 字地址。 |
| Xtensa | ESP8266 和 Xtensa 架构的 ESP32。`Backtrace` 地址对取指令地址。 |
| MIPS、MSP430、AArch64 | 使用对应架构的 GNU 工具或 `llvm-addr2line`，可粘贴 EPC、PC、ELR_EL1 等寄存器或地址列表。 |

保留带调试信息的构建产物及对应版本的源码。含 `ELF file SHA256` 的日志会校验指纹，匹配失败会停止解析。没有指纹时需自行核对固件版本。仅有 HEX、BIN 或专有调试格式的工程需要另外提供 ELF 符号文件。参考 [GNU addr2line](https://sourceware.org/binutils/docs/binutils/addr2line.html)。

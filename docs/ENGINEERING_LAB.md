# 工程实验工具

从 **工具 → 工程实验工具** 打开。下拉框可以切换工具。工程模板会在应用数据目录创建独立副本，随后打开项目导入窗口。其他文件路径均相对于当前绑定的工程。

| 工具 | 输入与运行条件 | 输出 |
| --- | --- | --- |
| 工程模板 | 四个模板均使用 CMake 和 Ninja。STM32F103C8 使用 Arm GCC。CH32V003 使用支持 `rv32ec/ilp32e` 的 RISC-V GCC。STC89C52RC 和 STM8S003F3 使用含相应后端的 SDCC。 | 在源码编译面板先配置再构建。Arm 和 RISC-V 生成 ELF，SDCC 生成 Intel HEX 格式的 IHX。 |
| 固件体积差异 | 同一架构、带符号表的两个 ELF。按编译单元归类还需要 DWARF。Python 依赖为 `pyelftools`。 | 按变化字节数排序的函数、变量或编译单元。符号缺少来源时显示未归属。数值为符号占用，Flash 文件填充和分区余量请看容量报告。 |
| 硬件规则检查 | 工程内的 `.kicad_sch` 或 `.kicad_pcb`，以及支持 JSON 报告的 `kicad-cli`。 | ERC 或 DRC 的规则、级别、图纸和关联对象。最近一次报告可在底部问题面板查看，或交给 Agent 审查。 |
| 总线解码 | CSV 的 `time` 列使用秒，其余各列使用 0 或 1，时间严格递增。将引脚映射到表头。`.sr` 和 `.vcd` 使用 `sigrok-cli` 及协议解码器。 | CSV 数字波形、I²C 地址和 ACK/NACK、SPI MOSI 字节或 UART 数据。内置解码支持七位 I²C、低有效 CS 的 8 位 MSB-first SPI 模式 0–3、UART 8N1。 |
| 多板回归 | 选择已连接串口的设备，勾选夹具就绪。共用用例支持 `send`、`wait`、`expect`、`assert`。指纹可选，来源标为用户提供。 | 逐板输出端口、结果、实测值、起止时间及跳过原因，可导出 JSON。 |

**CAN 分析 → DBC 信号解码** 使用当前 CSV 或 candump 记录和导入的 DBC，显示信号名称、缩放值与单位。选中信号可在独立设备标签按时间回放，送往波形、节点与报警。每次保留最多 12,000 个信号值，同时报告总数。此功能使用 Python 包 `cantools`。

**屏幕设计器 → 交互与画面回归** 支持录制最多 64 次控件点击。重放会核对命中的控件跳转、事件和目标页面的首帧像素。基准按设备和工程保存在当前客户端。选择步骤可下载 PNG，也可与相同分辨率的帧缓冲图或裁切后的实屏照片逐像素比较。差异以红色显示。

## STM32 OLED 示例

1. 创建 STM32F103C8 OLED 工程，进入源码编译面板配置并编译。
2. 在总线解码中输入 `oled-address.csv`。SCL、SDA 两列保持默认映射。可看到 `0x3C W` 和 `ACK`。这是随工程提供的教学采样。
3. 打开屏幕设计器。工程内的 `screen.signaldesk.json` 提供两个条纹画面。点击画布切换页面，可录制翻页并重放。实板示例用 PA0 低有效按键翻页。
4. 实板接线和引脚见模板 README。用逻辑分析仪记录自己的 SCL 和 SDA 后，可将采样文件放入当前工程并重新解码。

## 可选工具

多板用例可通过 `"fixtures": ["oled", "loopback"]` 指定所需夹具。每块板在夹具名称框中填写实际连接的设备，用逗号分隔。测试报告保存每块板的夹具、各步读数、执行时间和缺失项。

把对应工具目录加入 `PATH` 或 `SIGNALDESK_TOOLCHAIN_PATH`。Python 工具支持通过 `SIGNALDESK_LAB_PYTHON` 指定虚拟环境中的解释器绝对路径。在该环境执行 `python -m pip install cantools pyelftools`。CSV 总线解码和屏幕回归使用应用内置实现。
